# تصویر مقاله و ادامهٔ Render رایگان — ۱۶ نوامبر ۲۰۲۶

درخواست مالک: بارگذاری تصویر از همان فرم مقاله، یا استفاده از لینک اینترنتی؛ حفظ انتشار یک‌کلیکی و طراحی Settings، آزمون و انتشار مرحله و گزارش روی گیت.

## تغییر

- انتخاب فایل، برش/چرخش/نور، پیش‌نمایش و حذف تصویر در فرم مقاله اضافه شد. نسخهٔ WebP به همان مقاله با شناسهٔ آن متصل می‌شود؛ آخرین متن موجود حفظ می‌شود. متن و تصویر در یک commit ثبت می‌شوند. انصراف، تصویر قبلی را عوض نمی‌کند؛ فایل نامعتبر رد می‌شود و پیش‌نویس پس از reload می‌ماند.
- لینک مستقیم HTTPS در اعتبارسنجی مرورگر، ثبت Git و بررسی Python پذیرفته می‌شود؛ URLهای CDN دارای query یا بدون پسوند نیز مجازند. URL دارای رمز، HTTP، scheme نامعتبر، کنترل‌کاراکتر یا مسیر خارج از رسانه‌های مجاز پذیرفته نمی‌شود. تصاویر محلی باید واقعاً در مخزن یا رسانهٔ آمادهٔ انتشار موجود باشند؛ لوگو و پس‌زمینه همچنان رسانهٔ محلی‌اند.
- تصویر بیرونی صرفاً در مرورگر به‌صورت تصویر با `no-referrer` نمایش داده می‌شود؛ دانلود/proxy سمت سرور یا دورزدن hotlink/CORS ساخته نشد. پس از خطای دریافت در پنل، راهنمای بارگذاری فایل نشان داده می‌شود. لینک صفحهٔ وب/Drive preview به تصویر تبدیل نمی‌شود.
- گیت مالک GitHub، کنترل تعارض و عدم force push، وزیرمتن/روز و شب و ساختار اصلی حفظ شدند. Clinic، IntMed/AUS، حساب‌ها، secrets و داده‌ها در این مرحله تغییر نمی‌کنند. هیچ پست واقعی مالک به‌جای او ارسال نشد.

## شواهد

- پیش از پیاده‌سازی، آزمون JS لینک HTTPS را با محدودیت قدیمی رد کرد؛ بررسی Python نیز آن را به پوشهٔ uploads محدود می‌کرد. مرورگر نبودِ ورودی بارگذاری در مقاله را بازتولید کرد.
- پس از اصلاح، آزمون JS ثبت لینک خارجی و باقی‌ماندن کنترل فایل محلی/لوگوی محلی را پاس کرد؛ Python لینک‌های معتبر/نامعتبر را بررسی کرد. مرورگر واقعی با API و محتوای ساختگی، بارگذاری/برش/انصراف/فایل نامعتبر/reload، ثبت اتمی رسانه و مقاله، لینک بیرونی و نمایش آن در مقالهٔ عمومی را تأیید کرد. پنل در موبایل/شب overflow نداشت؛ تصاویر روز/موبایل بازبینی شدند.
- بازبینی مستقل یک ایراد مهم یافت: انصراف بعد از شروع Save و هنگام نوشتن IndexedDB، تصویر را از مقاله جدا می‌کرد ولی فایلِ آمادهٔ انتشار را باقی می‌گذاشت. آزمون با تأخیر واقعی در تحویل رویداد IndexedDB ابتدا ۶ تصویر به‌جای ۵ دید و شکست خورد. اکنون همان فایل جدید و object URL آن حذف و حذف در ذخیرهٔ محلی ثبت می‌شود؛ reload و انتشار فقط تصویر تأییدشده را نگه می‌دارند. شرط آزمون ضعیف نشد.
- همان بازبینی پنجرهٔ زمانی بین Cancel و پایان پاک‌سازی را نیز بررسی کرد: هنگام آماده‌سازی یا پاک‌سازی تصویر، انتشار کلی/مقاله و دریافت مجدد غیرفعال‌اند و خود handler انتشار نیز ثبت را رد می‌کند. بسته‌بودن واقعی dialog مستقل از زمان تحویل رویداد close بررسی می‌شود. آزمون ابتدا فعال‌بودن اشتباه Publish در این فاصله را نشان داد؛ پس از اصلاح، تلاش به انتشار در زمان تأخیر هیچ فایل/commitی نمی‌سازد و فقط تصویر تأییدشده بعداً منتشر می‌شود.
- مجموعهٔ کامل Node22 و ساخت تازهٔ اولیه موفق بودند. اولین CI (`43881152993`) پیش از آزمون‌های محصول، به خطای HTTP 503 در دریافت بستهٔ pinned ویرایشگر در setup برخورد کرد؛ موفق محسوب نشد. پس از اصلاح بازبینی، آزمون کامل/ساخت تازه و CI آخرین head دوباره بررسی می‌شوند؛ checksum و هیچ گیتی دور زده نمی‌شود.
- آزمون کامل، ساخت تازه، بازبینی مستقل، CI آخرین head و شناسهٔ واقعی انتشار پیش از تحویل تأیید و در PR مربوط ثبت می‌شوند. نتیجهٔ محلی، به معنی ورود به حساب واقعی مالک یا انتشار پست او نیست.
- شواهد نهایی این مرحله در [PR14](https://github.com/4mirgr/gerami-website/pull/14) ثبت می‌شود؛ این فایل و راهنمای مدیریت همراه همان کد روی گیت نگهداری می‌شوند.

## Render و Neon

تصویر جدید مالک انتخاب واقعی Free و **۰ دلار در ماه** را نشان می‌دهد؛ سرویس هنوز Deploy نشده است. راهنمای همین صفحه:

| بخش | مقدار |
| --- | --- |
| Secret Files | خالی |
| Health Check Path | `/healthz` |
| Registry Credential | `No credential` |
| Docker Build Context Directory | `.` |
| Dockerfile Path | `./Dockerfile` |

متغیرهای غیرمحرمانه: `CLINIC_ENV=production`، `TRUST_HTTPS_PROXY=1`، `CLINIC_DOCUMENT_STORAGE=database`، `CLINIC_DOCUMENT_BUDGET_MB=128`، `NEWSLETTER_ENABLED=0` و `DJANGO_CSRF_TRUSTED_ORIGINS=https://feat-member-access-hub.gerami-website.pages.dev`. نام مستعار پیش‌نمایش با API واقعی Cloudflare بررسی شد؛ اتصال به تولید نیست.

کلید Django با `openssl rand -hex 32 | pbcopy` روی مک مالک به کلیپ‌بورد می‌رود و فقط در مقدار `DJANGO_SECRET_KEY` در Render چسبانده می‌شود؛ مقدار محرمانه وارد گفت‌وگو یا Git نمی‌شود. `CLINIC_PROXY_KEY` مستقل با Generate ساخته و بعداً فقط از مسیر امن با Preview Cloudflare جفت می‌شود. اتصال pooled Neon در `DATABASE_URL` و اتصال direct در `DATABASE_URL_UNPOOLED` است؛ با Generate ساخته نمی‌شوند. نام branch/database/role و خالی‌بودن بانک مستقل هنوز تأیید نشده‌اند. مهاجرت، میزبان و آزمون HTTPS/پشتیبان واقعی باقی‌اند؛ PR7 فعال نمی‌شود و هیچ خرید/صورتحسابی مجاز نیست.

## نتیجهٔ انتشار و هماهنگی شاخهٔ Clinic

نسخهٔ اصلی در merge commit `d040d1aa40f2c3dbed616750cbf6e431f731b448` همان tree آزموده‌شدهٔ head `65b0ac31a2aa17aff10c37328599df74308a505a` است. CIهای آخرین head (`43882818014` و `43882818530`) موفق، مجموعهٔ کامل Node22 و ساخت تازهٔ `/tmp/gerami-article-images-final-20261116` موفق و بازبینی مستقل بدون یافتهٔ باز بود. پس از timeout درخواست merge، رویداد خودکار انتشار آغاز نشد و metadata PR باز ماند؛ Git main واقعاً commit بالا را داشت. ساخت Git همان شاخه در همان پروژهٔ مجاز Cloudflare از API مستند آغاز شد؛ بدون Direct Upload یا تغییر تنظیمات/گیت‌ها. انتشار اصلی `7a34aceb-1be9-445e-bf66-ec3d777e7619` مراحل clone/build/deploy را موفق گذراند. مرورگر واقعی دامنهٔ اصلی helper تصویر HTTPS، رد HTTP، گیت مدیریت و پاسخ 401 تنظیمات/کد بدون ورود، و سلامت صفحهٔ اصلی/IntMed را تأیید کرد؛ ورود واقعی مالک و ارسال پست او انجام نشد.

مالک در Neon نام‌های `production` / `neondb` / `neondb_owner` را اعلام کرد. ساخت یک دیتابیس خالی جدا به نام `clinic_preview` و انتقال مستقیم دو URL به Render راهنمایی شد؛ ایجاد واقعی آن، اتصال، مهاجرت یا میزبانی هنوز تأیید نشده‌اند.

کد منتشرشده به PR7 منتقل می‌شود تا هنگام فعال‌سازی حساب مشترک از دست نرود. صفحهٔ مستقل مقاله در خروجی HTML اولیه نیز تصویر و اطلاعات اشتراک‌گذاری را با URL امن/escape و no-referrer نگه می‌دارد؛ تست ابتدا نبود تصویر را نشان داد و پس از اصلاح موفق شد. آزمون کامل/ساخت/CI همان شاخه باید جدا تأیید شوند. این هماهنگی اجازهٔ فعال‌سازی Clinic نیست.
